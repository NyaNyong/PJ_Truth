# 🎮 진실보관소: Truth_Archive

## 📌 프로젝트 개요 (Overview)
<img width="1302" height="625" alt="image" src="https://github.com/user-attachments/assets/df6b870c-f18a-424f-a876-d8627be31038" />

2026학년도 1학기 디지털아트페스티벌 출품작으로, 근미래 디스토피아적 배경에서 정보가 선택적으로 공개되고 통제되는 사회 구조를 다루는 시리어스 게임입니다.
본 작품은 플레이어가 시스템의 일부로서 직접 행동함으로써,
“무엇이 진실인가”보다 “어떤 진실만 남도록 만들어지는가”를 체험하게 하고,
그 과정에서 정보의 이면에 존재하는 구조를 스스로 인식하도록 하는 것을 목표로 합니다.

제작 기간: 2026.03 ~ 2026.06 (약 3개월)

참여 인원: 5인

나의 역할: 인게임 시스템 설계, 개발 전반

사용 기술 및 툴: Unity, Claude

## 🙋‍♂️ 나의 역할 및 기여도 (My Contribution)

### 1. [직무 1: 시스템 기획 및 로직 구현] (기여도: 70%)

서사적 딜레마를 시스템과 데이터 로직으로 치환하여 게임 루프 설계

이중 플레이 루프(Day & Night) 기획: 낮(1인칭 서류 검열)과 밤(3인칭 현장 탐색)이 교차하며, 낮의 '검열 행위'가 밤의 '탐색 난이도 및 상호작용'에 영향을 미치도록 핵심 게임 루프 구조 설계.
동적 피드백(뉴스 송출) 시스템 로직 설계: 플레이어의 '단어 마스킹(검열) 강도'에 따라 다음 날 아침 송출되는 '공식 뉴스'와 '사설 뉴스'의 텍스트가 분기되도록 데이터 테이블 및 조건부 출력 로직 기획.
스테이지 기반 진행 및 분기 로직 설계: 스테이지 1~7까지의 정보 해금 순서를 통제하고, 플레이어의 최종 선택(폭로 vs 잠입)과 단서 수집률에 따라 6가지 멀티 엔딩으로 판별되는 내러티브 매트릭스 로직 설계.

### 2. [직무 2: 게임 개발] (기여도: 99%)

기획된 기믹과 상호작용을 Unity 엔진 위에서 실제 플레이 가능한 기능으로 100% 구현

1인칭 문서 검열 시스템 구현 (낮 페이즈):

마우스 이벤트를 활용한 '블랙 마커' 텍스트 마스킹 기능 및 타자기 대체어 입력 UI 프로그래밍.
'승인 도장' 클릭 시 화면 진동(Camera Shake), 효과음, 파티클 이펙트를 동기화하여 플레이어에게 '행위의 무게감'을 주는 시각/청각적 피드백 구현.

3인칭 탑다운 탐색 및 상호작용 구현 (밤 페이즈):

2D 도트 캐릭터의 WASD 이동, 애니메이션 제어 및 충돌 처리 개발.
Raycast를 활용한 NPC 및 오브젝트(CCTV, 쓰레기통 등) 상호작용 시스템 개발. 스테이지별 조건에 따른 NPC 다이얼로그 분기 시스템(Dialog System) 연동.

화이트보드 추론(레드 스트링) 시스템 프로그래밍:

획득한 단서 카드를 UI 캔버스 상에 인스턴스화하고, 마우스 드래그 앤 드롭으로 노드 간 선(Line Renderer 활용)을 연결하는 기능 개발.
'실종 → 이송 → 기록 삭제'와 같은 특정 논리 순서 쌍을 검증하는 알고리즘을 작성하여, 정답 시 붉은 실이 발광하고 진실 텍스트가 해금되는 기믹 구현.

## 🛠️ 문제 해결 및 개선 과정 (Trouble Shooting)

### 🚨 1. 플레이어의 '검열 행위'에 대한 시각적 피드백 및 감정적 동기 부족

상황(Situation): 초기 기획 단계에서 낮 페이즈의 텍스트 마스킹(검열) 작업이 단순한 클릭 퍼즐로 인식되어, 기획 의도인 '죄책감'과 '시스템에 순응하는 기분'을 전달하지 못함.

원인 분석(Task): 검열한 결과가 게임 내 미치는 피드백이 부족하였음.

해결 과정(Action)
시스템 기획 측면: 낮과 밤 페이즈 사이에 '결과 노출(아침) 페이즈'를 신설. 플레이어의 마스킹 퍼센테이지(검열 강도) 데이터를 저장하여, 다음 날 아침 '공식 뉴스' 텍스트를 동적으로 교체하는 로직을 구현함.

결과(Result): 자신의 사소한 클릭(검열 데이터) 하나가 게임 내 결과에 직접적 영향을 미친다는것을 피드백받게 됨. 단순 검열게임이 아닌, 선택에 따른 무게를 느끼게 하여 핵심 메시지에 몰입 가능하게 함.

### 🚨 2. 방대한 텍스트 데이터의 하드코딩으로 인한 스크립트 비대화 및 유지보수 문제

상황(Situation): 스테이지 1~7에 걸친 가이드라인, 낮/밤 뉴스 내용, 사건 일지, NPC 대화 등 게임 내 텍스트의 양이 매우 방대함.

원인 분석(Task): 초기에는 텍스트 데이터를 C# 스크립트 내에 하드코딩하려 했으나, 스크립트 길이가 지나치게 길어져 가독성이 떨어짐. 또한 오타 수정이나 기획(스토리) 변경 시마다 유니티 스크립트를 열고 재컴파일해야 하는 심각한 비효율성이 발생함.

해결 과정(Action):

텍스트 데이터를 코드에서 완전히 분리하여 JSON 포맷으로 외부에서 관리하는 데이터 주도형(Data-Driven) 시스템을 구축함.
C# 코드에서는 플레이어의 검열 결과값이나 스테이지 진척도와 같은 '동적 변수'와 로직만 관리하도록 리팩토링함.
게임 실행 시 혹은 특정 페이즈 진입 시 JSON 파일에서 해당 스테이지에 필요한 텍스트 및 대사 데이터만 파싱하여 UI에 바인딩하도록 구현함.

결과(Result): 코드의 가독성과 유지보수성이 대폭 향상됨. 텍스트 수정 시 빌드를 다시 해야하는 게 아닌, 외부 JSON 파일만 수정하면 게임 내 스토리가 즉각 반영되도록 하여, 기획 단계의 이터레이션(반복 수정) 속도를 획기적으로 단축시킴.
